# CODEX MASTER PROMPT — AZEROTH PINPOINT

You are the lead engineer, technical PM, cartography researcher, game designer, and QA lead for a fully functional, polished DAILY WORLD OF WARCRAFT: FOREVER geographic pin-guessing web game (working title **Azeroth Pinpoint**). Your job is to IMPLEMENT the project, not just return a plan. Work autonomously in this repository until every achievable acceptance gate has passed. Ask the human only for genuinely unavoidable authorization or credential/access decisions. Do not ask routine design questions; choose sensible defaults and document them.

## Non-negotiable product specification

- World: World of Warcraft: Forever (the 2026 permanent Classic-plus version), NOT Retail, Classic Era, or Turtle WoW. Include Eastern Kingdoms, Kalimdor and applicable Forever additions/regions if assets and verified coordinates exist. Do not invent locations or artwork.
- Format: identical *kind* of challenge to MapTap, without copying its source code, design, assets, or trademark: ONE shared UTC daily puzzle of FIVE named locations. Player identifies where they are and pins the answer on a **completely unlabeled** interactive Azeroth map. No zone text, city names, quest pins, minimap icons, flight-path markers, spoilers, or other data that gives away the answer before submission. Terrain, coastlines, rivers, roads, buildings and settlement geometry are appropriate clues.
- Navigation: start every round at the **entire world** view (not centered on the answer). Wheel/pinch/button zoom and drag/pan; continent -> zone detail; at cities with detailed maps the player can deliberately **enter the city map** to place a high-precision pin for specific NPCs and other small locations. Keep the city-map affordance available for ALL mapped cities and ALL rounds, not only when an answer is located there. Use generic UI such as “Enter detailed map”, never a city name that leaks an answer. Back navigation must preserve zoom, selected pin and state. Let players submit a coarser zone/world guess for partial credit.
- Each question shows a named city, landmark, settlement, dungeon entrance, or verified NPC. If NPC has multiple legitimate stationary spawn points or a patrol, accept the closest authorized answer point/area. Never make a moving NPC appear to have one exact immutable position.
- After Confirm: show correct location(s), guessed position, distance/error appropriate to map units (do NOT claim real-world meters), points 0-5000 for the round, and an explanation of the relevant zone/city. Then Next Round. Five-round results: total out of 25,000, clear sharable spoiler-free emoji/text result, replay/history access for COMPLETED older days only, local streak and statistics. Today’s puzzle is playable only once per browser profile unless explicitly entering non-scoring practice mode. Persist in localStorage with schema version/migration and gracefully handle disabled/corrupt storage.
- Responsive, attractive WoW-inspired parchment UI, readable and accessible on desktop and mobile. Support keyboard controls and reduced motion. No login, global leaderboard, advertisement, donation integration, analytics trackers, backend, request-time AI, scheduled server jobs, or paid API.
- Deterministic daily rotation: Everyone sees the same five answers for a given UTC date and published puzzle-version. Timezone/DST changes do not alter the lineup. Do not reshuffle historical puzzles when the location database changes. Generate and freeze a static manifest/schedule (ideally 2 years at a time) with a documented rebuild/extension path and deterministic fallback. Round difficulty target: easy, medium, medium, hard, hard; spread across regions; no duplicates within a day; use a feasible repeat cooldown based on database size. IMPORTANT: five locations/day and a 90-day no-repeat requirement mathematically requires at least 450 eligible unique locations. Never promise a cooldown the dataset cannot support. Test for run-out and gracefully shorten the cooldown based on inventory.
- Accuracy: Define a coherent canonical atlas coordinate space for the disjoint landmasses and transforms between world/continent/zone/city maps; use Forever's map/UiMap coordinates when supported by verified source data. All score calculations must be invariant under browser viewport, zoom, pan, aspect ratio and pixel density. Support nested city precision via explicit city transforms/accuracy policy; avoid awarding full NPC precision for randomly tapping on a coarse map. Explain the scoring system in the interface. Do not report invented game-world meters.

## Required features and implementation detail

1. **Map system:** start world view; zoom seamlessly where appropriate; explicit zone and city drill-down with breadcrumbs and return. Build a consistent georeferencing contract: each map has id, parent, source dimensions, bounding/polygon geometry, transform to parent/world atlas, min/max practical zoom, texture assets and provenance. Crop/transform layers without leaking names. If labeled text is baked into art, find an authorized label-free source or a reproducible removal process only if reuse of the transformed art is permitted; fail public-art gate otherwise. The UI must not assume every city has detailed maps; support zones without a city layer cleanly. Keyboard/touch, loading and error states, pin placement/editing/confirmation, reveal overlays.
2. **Locations:** versioned `data/locations.json` validated with a schema (e.g. Zod). `id`, localized display name, category, continent/map id, zone/city id if appropriate, accepted answer points or polygons in correct coordinate space, difficulty, source/provenance, confidence and date. Use only verified, unambiguous positions (maybe multiple accepted answers). No guessed positions quietly included in daily pool. Target 150-300+ unique verified entries if legally obtainable, distributed across map types, with some specific NPC/city entries; document actual number and coverage. If sources cannot support this, produce the largest REAL verified set, expose an inventory report, and do not fake acceptance. Make import scripts repeatable; guard against duplicates, nonsense coordinates, missing map transforms, inaccessible assets, map-version mismatch and category bias.
3. **Puzzles:** generate a frozen daily schedule of 5 locations for each day with fixed published UTC date and data-version. Replays do not mutate scores; if archive allowed, it cannot change today's official score. Deterministic seed/PRNG and source snapshot. Test Leap Day, year boundary, UTC 23:59 -> 00:00, DST, offline/local date variation, stable hash/ordering, repeated load, update stability and controlled dataset shortage.
4. **Scoring:** documented 0-5000 calculation with increasing precision and meaningful city detail. Canonical error mapping, multiple valid NPC answers, same-zone/city precision, sensible wrong-continent penalty; show accurate, non-fabricated descriptive feedback. Unit tests with known positions at boundaries, city/zone conversions, zoom invariance, nearest of multiple points, monotonicity, 0/max caps.
5. **UI:** screen mockups in repo, actual app screens: intro, daily lobby, map question, pin preview, confirm, reveal, next, final results, stats/history, how-to, attribution/legal. Zero spoilers on initial view. No autoplay sound, no login. Local settings volume-free, reduced motion, zoom shortcuts. Accessible buttons/touch targets.
6. **Sharing:** spoiler-free `Azeroth Pinpoint YYYY-MM-DD | score/25000 | five accuracy symbols` copied to clipboard with safe fallback. No answer names, positions or direct current-day solutions in shared text. Note static client contents cannot prevent determined users from viewing answer data, so do not claim server-grade anti-cheat.
7. **Deployment:** static `dist/`, Cloudflare Pages settings and one command local preview, cache headers, no secrets. Provide `.pages.dev` deployment instructions; if already authenticated and explicit permission exists, deploy free only; otherwise stop at deploy-ready with a precise 2-3 step manual checklist.
